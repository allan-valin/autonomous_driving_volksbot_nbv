# Setup

What to install on each machine, and how to build. Two machines are assumed —
a robot and an operator laptop — but both roles can live on the robot, and on a
flaky network they should (see [NETWORKING.md](NETWORKING.md)).

Developed against **ROS 2 Jazzy on Ubuntu 24.04**. Humble works with minor
adjustments to the Nav2 plugin names in `nav2_params.yaml`.

---

## 1. Which machine needs what

| Component | Robot | Laptop |
|---|---|---|
| `volksbot_driver` (base driver, URDF, joystick config) | yes | no |
| `sllidar_ros2` (LiDAR driver) | yes | no |
| `phidgets_drivers` (IMU) | yes | no |
| `robot_state_publisher`, `teleop_twist_joy`, `xacro` | yes | no |
| `robot_localization`, `imu_filter_madgwick`, `laser_filters` | no | yes |
| `slam_toolbox` | no | yes |
| `navigation2`, `nav2_bringup` | no | yes |
| `frontier_exploration_ros2` | no | yes |
| **this package** | yes | yes |

"Robot only" and "laptop only" are about where the node *runs*. Installing
everything on both machines is simpler and costs nothing but disk.

## 2. Workspace

```bash
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src
```

Clone this repository:

```bash
git clone https://github.com/allan-valin/autonomous_driving_volksbot_nbv.git
```

Clone the frontier explorer next to it (not inside it):

```bash
git clone https://github.com/mertgulerx/frontier_exploration_ros2.git
```

The platform packages — `volksbot_driver` and `sllidar_ros2` — are not public
ROS distro packages. Obtain them from whoever supplies your robot and place
them in `~/ros2_ws/src` as well. On a robot that already has them installed in
its own workspace, source that workspace before launching instead of copying
them.

Expected layout:

```
~/ros2_ws/
├── build/   install/   log/        <- generated by colcon, do not edit
└── src/
    ├── autonomous_driving_volksbot_nbv/   <- this repo (package volksbot_nbv_bringup)
    ├── frontier_exploration_ros2/         <- upstream, used as-is
    ├── volksbot_driver/                   <- platform, supplied separately
    └── sllidar_ros2/                      <- platform, supplied separately
```

## 3. Dependencies and build

```bash
source /opt/ros/jazzy/setup.bash

cd ~/ros2_ws
rosdep install --from-paths src --ignore-src -r -y

colcon build --symlink-install
source install/setup.bash
```

`--symlink-install` means edits to YAML and launch files take effect without a
rebuild, which matters a lot while tuning.

To avoid re-sourcing in every terminal:

```bash
echo "source /opt/ros/jazzy/setup.bash" >> ~/.bashrc
echo "source ~/ros2_ws/install/setup.bash" >> ~/.bashrc
```

### If you use conda

A conda environment on `PATH` breaks `colcon build`: its Python is picked up
instead of the system one, and `ament_cmake_python` then installs into the
wrong prefix or fails outright. Run `conda deactivate` before building, and
keep it deactivated in terminals that launch ROS nodes.

## 4. Verify

```bash
ros2 pkg list | grep -E 'volksbot_nbv_bringup|frontier_exploration_ros2|laser_filters'
```

This package ships no executables of its own — only configuration and launch
files — so `ros2 pkg executables volksbot_nbv_bringup` is correctly empty.

Check that the configs actually installed into `share/`, since the launch files
resolve them from there rather than from the source tree:

```bash
ls $(ros2 pkg prefix volksbot_nbv_bringup)/share/volksbot_nbv_bringup/config
```
